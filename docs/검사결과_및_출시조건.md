# 모찌펫 0.4.1 소스 보완 — 검사 결과와 남은 조건

작성일: 2026-11-05. 범위: 이 대화에 첨부된 v0.4 자료의 소스 개선. 외부 보안 업체의 감사가 아닙니다.

## 입력 자료

- `mochipet_oneclick_src/project.zip`: 게임 프로젝트 원본을 실제로 풀어 확인했습니다.
- `모찌펫RPG_v0.4_Windows_설치.exe`: PE 인증서 테이블 확인. 임베디드 Authenticode 서명 테이블이 없습니다. 결과와 SHA-256은 `original_input_facts.json`에 기록했습니다.
- 원본 Go 설치기의 Go 소스는 첨부 자료에 없어 전체 동작을 소스 수준에서 감사하지 못했습니다. 바이너리의 문자열·심볼만으로 안전성을 판정하지 않았습니다.

## 원본에서 직접 확인한 보완 필요 지점

| 항목 | 원본 코드에서 확인한 점 | 수정 소스 |
|---|---|---|
| 저장 교체 | `FileAccess.WRITE`로 본 저장을 직접 덮어씀 | 임시 파일 작성/재읽기/이전 정상 기록 백업/교체 오류 처리 |
| 입력 검증 | 대부분의 저장 값을 검증 없이 복사. 레벨·지역만 범위 제한 | 저장 크기, 자료형, 유한 숫자, 스탯 범위, 이름 길이, ID 목록 검사 |
| 초기화 | 클릭 한 번으로 바로 초기화 | 명시적 확인 + 직전 기록 백업. 실패 시 중단 |
| 클릭 영역 | 캐릭터/몬스터 개별 `regions`를 만들지만 실제 적용은 화면의 넓은 L자 다각형 | 해당 계산 제거. 기본 일반 창, 미검증 투명 오버레이 비활성화 |
| 창 복구 | 첫 실행부터 화면 크기의 테두리 없는 항상 위 창 | 닫기 버튼이 있는 일반 창, 일시정지/종료 버튼 |
| 화면 API | `DisplayServer.screen_get_rect(0)` 사용 | 문서화된 `screen_get_usable_rect()`로 교체 |
| 다중 실행 | 인스턴스별 저장 충돌 보호 없음 | 앱 전용 잠금 디렉터리 + 소유 PID 확인. 확인 실패 시 중단 |
| 자원 사용 | 명시적 FPS 상한 없음, 처치/클릭마다 디스크 기록 | 30 FPS 상한, 최소화·정지 시 전투 중단, 10초 단위 저장 |
| 이동 방향 | 몬스터가 어느 쪽이든 왼쪽 위치로 접근 | 펫 위치에 따라 접근 방향을 분리 |
| 배포 구조 | 다운로드 설치기의 동작 전체를 검증하지 못함 | 공식 내보내기 결과물을 포함하는 오프라인 NSIS 소스 제공. EXE는 미생성 |

이는 원본에서 악성코드를 발견했다는 뜻이 아닙니다. 반대로 원본의 안전함을 증명한 것도 아닙니다.

## 이 환경에서 실제로 수행한 확인

- **32/32 정적 정책 및 파일 구성 검사 통과.** 대상 문자열/패턴과 파일 구성 조건을 검사한 것입니다. 컴파일러·정적 의미 분석기·악성코드 탐지기의 검사는 아닙니다.
- 펫 28종 × 7가지 상태 × 2프레임 = 392개 PNG와 몬스터 8개 PNG의 존재 여부, PNG 시그니처, 크기, 청크 CRC 확인.
- 원본 이미지 파일과 수정 프로젝트 이미지 파일의 SHA-256 대조. 이미지 리소스는 원본과 동일합니다.
- 기존 실행 파일을 변조하거나 재서명하지 않았습니다. 새 실행 파일을 만들었다고 주장하지 않습니다.

검사 명령: `python tests/static_audit.py --report docs/static_results.json`

## 출시 전 통과 조건

1. 신뢰할 수 있는 출처에서 Godot와 내보내기 템플릿을 준비하고 버전·체크섬을 검증합니다. 종속 엔진의 알려진 취약점도 확인합니다.
2. 파싱, 저장소, 리소스 테스트를 모두 실행합니다. 빌드 스크립트는 이 단계가 실패하면 중단하도록 작성했습니다.
3. 일반 사용자 계정의 깨끗한 Windows 환경에서 네트워크를 끊고 설치·첫 시작·캐릭터 선택·전투·상점·저장·종료·재시작·삭제를 확인합니다. 이는 사용자에게 보안 기능을 끄라고 요청하는 절차가 아닙니다.
4. 파일/레지스트리/프로세스/네트워크를 관찰하여 앱 전용 경로 밖의 예상하지 못한 변경과 불필요한 통신이 없는지 확인합니다. 빌드 소스만으로 이 동작을 보증하지 않습니다.
5. Defender 실시간 보호를 유지한 상태에서 검사합니다. 백신 예외 설정, 관리자 실행 강요, SmartScreen 전체 해제는 배포 요건이 아닙니다.
6. 1시간 이상 실행, 최소화, 화면 잠금, 절전/복귀, 저배터리, 다중 실행, 디스크 부족, 저장 파일 손상, 초기화 취소를 확인합니다.
7. 투명 오버레이는 별도의 네이티브 창 시험을 통과한 뒤에만 빌드 설정에서 활성화합니다. Windows의 `mouse_passthrough` 동작은 다른 앱으로의 클릭 전달까지 실측해야 합니다.
8. 정식 코드 서명/배포 경로를 준비합니다. 코드 서명이 있더라도 새로운 파일의 SmartScreen 경고가 반드시 없어지는 것은 아닙니다.

## 공개 전까지의 결론

**소스 개선은 수행했지만, 보안 검증된 실행판이나 안정성 검증 완료판은 아닙니다.** 현재 일반 사용자 배포는 권하지 않습니다. 이 보고서와 소스를 개발자 검토/빌드/테스트의 입력으로 사용하세요.
