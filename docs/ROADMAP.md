# 웹 서비스 개발 순서

- Phase 1: React·Phaser 로컬 플레이, 자동 전투·육성·상점·레벨 20·저장·반응형 구현. 실행 검증 범위는 [웹 보고서](WEB_PHASE1.md) 참고.
- Phase 2: NestJS 모듈형 API, PostgreSQL·Prisma 스키마/마이그레이션, 게스트·계정, 서버 소유 보상·트랜잭션, PC/모바일 동기화와 자리 비움 보상. [백엔드 설계](WEB_BACKEND_PLAN.md) 참고.
- Phase 3: PWA, 지원 브라우저의 Document Picture-in-Picture, MBTI 질문, 인벤토리·추가 스킬, 실제 모바일·접근성·성능 개선.
- Phase 4: Colyseus 온라인 월드, 서버 판정 레벨 20 해금, 이동 동기화·친구·채팅·협동 전투.

실제 모바일 브라우저·Safari/Firefox와 저사양 기기에서의 검증, 밸런스 조정, 라이선스·이미지 권리 결정은 별도로 필요합니다. 다음 목록은 이전 Godot 개발 계획의 기록입니다.

# 개발 로드맵

아래는 앞으로 할 일이며 구현 완료 목록이 아닙니다. 일정·출시일·검증 완료를 약속하는 문서가 아닙니다.

## 1. 개발 기준점 확립

- [ ] Godot 4.7.2에서 가져오기·파싱·저장 테스트를 실제 실행한다.
- [ ] Windows와 macOS 일반 창에서 선택·전투·상점·저장·종료를 확인한다.
- [ ] 재현 가능한 Windows 검토 빌드를 만들고 설치·제거를 검증한다.
- [ ] macOS 내보내기 설정과 실제 앱 검증 경로를 추가한다.

## 2. 바탕화면에서 보이는 사냥

- [ ] 플랫폼 창 처리와 게임 로직을 분리한다.
- [ ] 투명 창·클릭 통과·항상 접근 가능한 종료/일시정지를 실기기에서 검증한다.
- [ ] 화면 하단 좌우 이동을 화면 내부의 안전한 자유 이동으로 확장한다.
- [ ] 몬스터 이동·공격·처치 애니메이션과 스킬 이펙트를 추가한다.
- [ ] 다른 프로그램 입력 방해, 다중 모니터, 배율, 절전·복귀를 확인한다.

## 3. 육성·상점·스킬

- [ ] 캐릭터마다 실제로 다른 기본 스킬 효과 1개를 구현한다.
- [ ] 별도 스킬 구매/장착, 장난감 보유/사용, 음식 인벤토리를 설계한다.
- [ ] 경험치·코인·가격·스탯 상한의 균형을 검증한다.
- [ ] 오프라인 레벨 상한 20을 유지하는 회귀 테스트를 추가한다.
- [ ] MBTI 설문 추천과 자유 선택을 함께 제공한다. 추천은 재미용으로 표현한다.

## 4. 온라인 전환 — 별도 서버 필요

- [ ] 20레벨 진입 자격, 계정 생성/로그인, 캐릭터 연결 정책을 정한다.
- [ ] 로컬 JSON을 서버 경제의 신뢰 가능한 기록으로 그대로 수용하지 않는다.
- [ ] 온라인 레벨·재화·아이템·전투 보상의 서버 검증과 동기화 정책을 설계한다.
- [ ] 여러 기기, 계정 복구, 중복 연동, 데이터 충돌·위변조 대응을 검토한다.
- [ ] 다른 유저와 만나기, 협동 콘텐츠와 커뮤니케이션 범위를 정한다.
- [ ] 인증키·운영 DB·개인정보는 이 클라이언트 저장소에 넣지 않는다.

## 5. 공개 배포

- [ ] 코드·캐릭터 이미지의 권리/라이선스를 결정한다.
- [ ] 정식 배포자 서명·공증·스토어 경로를 검토한다.
- [ ] 업데이트, 저장 호환성, 제거, 충돌 복구 정책을 정한다.
- [ ] 검사한 실행판만 릴리스하고 실제 검증 범위와 미확인 항목을 함께 적는다.
